## Purpose
Three fixes that keep RED from changing the host app or trusting more than it must.
- In an API-only host, RED adds cookie, session and flash middleware to the host's whole stack, so
  every API endpoint gets cookie sessions. They belong to the dashboard alone.
- The layout loads nine files from jsDelivr with no integrity hash. Two of them are generated by
  jsDelivr rather than published by their package, and one comes from a git tag that can move.
- The gemspec admits concurrent-ruby versions with three known CVEs, and its comment says RED uses
  no ReadWriteLock, which is false.

## User stories
- As a developer with an API-only app, I want installing RED to leave my API's middleware alone,
  so that nothing in my app starts issuing session cookies.
- As a developer with an API-only app, I want the dashboard to work fully: login, forms, flash
  messages and the language picker.
- As a developer, I want the dashboard to refuse a CDN file whose bytes have changed.
- As a developer, I want RED's dependency floor to keep vulnerable concurrent-ruby versions out of
  new bundles.

## Requirements (EARS)

### API-only hosts
- **REQ-1.** Where the host app is API-only, RED shall add no cookie, session or flash middleware
  to the host app's middleware stack, so a host endpoint that writes the session still fails as
  it does without RED.
- **REQ-2.** Where the host app is API-only, the dashboard shall keep a working session for its own
  requests: the login, a CSRF-protected form submission, the flash message after it, and the
  language picker all work.
- **REQ-3.** Where an API-only host runs its own session middleware, the dashboard shall use the
  host's session rather than replace it.
- **REQ-4.** Where the host app is API-only and runs no session middleware of its own, the
  dashboard's session cookie shall be named `_rails_error_dashboard_session`.

### CDN files
- **REQ-5.** The dashboard layout shall load every script and stylesheet it takes from jsDelivr
  with an `integrity` hash and `crossorigin="anonymous"`.
- **REQ-6.** The layout shall load each jsDelivr file from an npm package at an exact version.
- **REQ-7.** Each integrity hash in the layout shall be the SHA-384 of that exact file, checked
  against a copy kept in the repository.

### concurrent-ruby
- **REQ-8.** The gem shall require concurrent-ruby 1.3.7 or later, within 1.x.

### Docs
- **REQ-9.** The gemspec comment shall describe RED's real use of concurrent-ruby, `CLAUDE.md`
  shall list the files the layout loads from CDNs, and the FAQ (and its `_reference/` mirror)
  shall say the dashboard works inside an API-only app. [untested: prose, verified by reading]

## Out of scope
- Vendoring or self-hosting the CDN files, and a Content Security Policy for the dashboard.
- Google Fonts (its CSS is generated per browser and cannot take an integrity hash), and the fonts
  and images a stylesheet loads in turn.
- The live-updates client, pinned in #308.
- An option to keep app-wide sessions in API hosts.
